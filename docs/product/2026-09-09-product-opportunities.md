# Smallest Agent：产品优化与下一阶段功能设计

日期：2026-09-09。依据当前工作区代码（含未提交改动）进行静态评估，以 Electron 桌面端为主要体验对象，交叉检查 Rust/GPUI 端。本文没有运行应用、调用真实模型或进行用户访谈；体验影响与收益属于待验证的产品判断。

## 1. 产品方向

建议下一阶段优先服务独立开发者与 AI 工具爱好者：围绕本地项目，完成代码理解、改动审阅和文档整理，并留下可检查、可继续使用的成果。

产品主张：**一个知道项目背景、能把任务做完，并让你看清结果的轻量 Agent 工作台。**

README 明确强调 Agent 工程教学，因此这个定位是建议，尚非已确认的产品战略。保留 CLI 的最小循环与分阶段学习路径；桌面端围绕一个高频任务逐步产品化。若目标仍以教学为主，应将下文的“运行实验室”提升为首要新功能。

建议先验证“理解一个陌生仓库并形成可引用的项目说明”这一场景。它能串起项目、检索、工具、记忆和成果，同时第一版可以只读运行。

## 3. 优先修复的体验问题

| 优先级 | 观察到的实现 | 用户影响 | 建议与验收 |
| --- | --- | --- | --- |

## 4. 新功能设计

### Feature A：任务模式与成果卡片

**用户需求：**“我让它理解项目、整理文档，需要知道现在做到了哪一步，最后能拿走什么。”

**入口与流程：**新对话保留自由聊天入口，同时提供“理解项目”“整理文档”“审阅改动”三个任务入口。进入任务后，确认目标和预期成果；长任务展示简短执行计划及真实步骤状态；完成后给成果卡片。

**最小版本：**

- 先支持“理解项目”，输出项目结构、运行方法、关键文件与待确认事项。
- 任务状态为待开始、进行中、待用户处理、待验收、已完成、失败、已停止；模型结束输出只进入待验收。
- 展示实际读取的文件、完成的工具调用、已知错误和结果引用。没有步骤事件的 Provider 仅显示“执行中”。
- 成果卡片显示摘要、引用文件、打开/导出入口和“采用结果”；支持继续补充要求。
- 普通对话不强制经过计划确认；短任务直接执行。没有确定分母时不展示百分比进度。

**关键边界：**“停止运行”与“撤销文件改动”分别表达；中断任务保留已有结果，不承诺从任意工具内部断点恢复。

**验收：**用户能在不翻聊天记录的情况下找到最终成果与依据；重启后任务状态、成果与会话保持关联；失败不能呈现为已完成。

**指标：**任务采用率、提交目标到结果采用的时长、每任务补充背景的次数。

**依赖与工作量：**需要会话之外的任务/运行元数据和稳定事件标识；中等工作量。首版不引入复杂任务看板。

### Feature B：项目上下文面板

**用户需求：**“这次回答究竟看了哪些资料？为什么换个会话又要解释项目背景？”

**入口与流程：**输入框上方显示“本次资料”，支持通过 `@` 选择项目文件、固定的项目说明与相关历史结论；点击可查看片段、来源、更新时间，并决定是否用于本轮。执行后补充实际检索命中的资料。

**最小版本：**

- 明确区分“用户选中的资料”与“执行时实际读取的资料”。
- 支持文本文件/Markdown 与已有项目事实；显示文件变动和索引刷新状态。
- 用户能排除某条事实用于本轮，也能跳转到现有记忆设置永久纠错。
- 提供项目内会话标题/正文关键词搜索和原消息跳转；历史语义检索作为后续扩展。
- 对上下文压缩显示简短说明，标明哪些内容已摘要化；上下文占用若来自估算应明确标注。

**关键边界：**当前项目之外的资料需要显式选择；删除会话时同步删除其搜索记录；发送前后区分资料版本，不能把已变更文件冒充本次输入的快照。外部 CLI 的上下文可见范围依据其实际协议能力呈现。

**验收：**用户能解释一条回答的资料来源；项目 A 的事实不会自动出现在 B；文件刷新后回答能引用新内容；删除来源后搜索不返回旧记录。

**指标：**重复补充背景的次数、找到旧结论的用时、引用来源打开率。打开率是行为信号，不等于答案正确率。

**依赖与工作量：**复用 facts、RAG 与项目目录；首版中等工作量，完整历史语义检索另行评估。

### Feature C：改动审阅与保留方案

**用户需求：**“让我先看清它改了什么；试另一个方案时，之前的结果还在。”

**入口与流程：**文本写操作出现可读 diff；运行结束后可集中查看受影响文件。用户可从某条消息创建新方案，对比两个结果。

**最小版本：**

- 优先覆盖内置文件工具的文本创建与编辑，保留现有权限模式。
- 写前记录该文件的实际内容与版本标识，审批时显示相应差异。
- “从这里尝试另一版”复制该点之前的会话记录到新会话，保留原会话。
- 对本工具写入且此后未变化的文本文件提供撤销；出现用户或其他进程的新改动时转入冲突审阅。

**关键边界：**会话分支不自动代表文件系统分支。首版方案比较以只读/生成建议为默认；两条分支若需实际改文件，应先有独立工作目录方案。外部 CLI、shell 与远程操作不承诺统一撤销。

**验收：**审批的差异与最终写入一致；拒绝不写；撤销不会覆盖后续人工修改；创建新方案后原答案仍可查看。

**指标：**用户准确理解改动的比例、审阅用时、误改反馈数量。撤销次数单独看无法说明产品更好或更差。

**依赖与工作量：**diff 展示可作为小切片先交付；可靠写入基线、冲突检测和分支属于较大工作量。当前编辑重发会截断历史，见 [编辑重发](/Users/royzeng/lab/smallest-agent/electron/renderer/src/App.tsx:487)。

### Feature D：可复用任务模板

**用户需求：**“上次整理文档的效果很好，下次换一份资料就能再跑。”

**入口与流程：**从系统提供的任务入口开始；完成并采用结果后，点击“保存为模板”，下次只填可变输入。

**最小版本：**

- 系统先提供“理解项目”“整理文档”“审阅改动”三个模板；第一轮发布只打磨其中一个。
- 模板包含目标、输入字段、资料选择规则、输出结构、验收项、所需能力及默认引擎设定。
- 执行前提示缺少的资料或能力，并提供对应配置入口。
- 用户模板保存结构化设定，不复制旧会话中的密钥、附件内容或完整历史；新执行绑定当前输入。
- 每次执行记录模板版本，修改模板不会改变旧结果的解释依据。

**增量价值：**现有 AgentDef 已能配置提示词、模型与工具；任务模板新增输入表单、输出结构和验收项，复用其执行配置。

**验收：**同一个模板可以针对两个项目生成各自的结果；缺必填输入不能无提示启动；项目资料不串用；用户可追溯运行使用的模板版本。

**指标：**首次任务启动率、模板二次使用率、模板任务采用率。

**依赖与工作量：**固定模板入口较小；从结果提炼用户模板需要 A 的成果与运行信息，中等工作量。

## 5. 两个候选扩展

**运行实验室：适合强化原有教学定位。**把当前会话中的代表性问题保存成带验收项的用例；在同一输入和资料快照下对比模型/提示词，查看工具调用、引用、评分与耗时。复用 CLI Eval，新增桌面操作与结果比较。首版仅支持只读任务，手动确认预期；LLM 裁判得分与可验证检查分开展示。用量缺失时标记未知；成本需要有来源和版本的价格配置，包含摘要、核查和子任务调用。其价值应通过“用户是否更快选出适合自己的配置”验证。

**自动化结果收件箱：适合已有重复任务之后。**复用 Rust 端间隔自动化的经验，新增每次运行记录、变化摘要、失败原因和暂停入口。仅有值得关注的变化时通知；应用关闭时不承诺运行，重新打开后明确补跑规则。先验证模板被重复使用，再决定是否投入 Electron 迁移与持续调度。

## 6. 交付顺序与取舍

| 阶段 | 交付内容 | 推进依据 |
| --- | --- | --- |
| 第一阶段：可信的首次体验 | 修复附件链路、启动按能力降级、一个“理解项目”入口、可检查的结果卡 | 新用户无需指导即可完成一次真实项目任务 |
| 第二阶段：持续使用 | 项目上下文面板、资料刷新、会话搜索、任务状态持久化 | 复用同一项目时，解释背景与找结果的时间下降 |
| 第三阶段：扩展到改动与复用 | 可读 diff、受限撤销、会话方案保留、保存任务模板 | 结果采用与模板复用有明确需求，再投入更复杂的执行保障 |
| 候选方向 | 运行实验室或自动化结果收件箱 | 由目标用户与实际重复任务决定优先顺序 |

以上是依赖顺序，不是工期承诺。建议先选择一个主交付客户端，维护另一端的能力差异说明，避免每个功能都承担双端同步成本。

首轮资源集中于一个端到端场景。插件市场、通用流程画布、更多模型接入与复杂多 Agent 编排暂不优先；当前接入和执行基础足以验证核心价值。

## 7. 如何验证方向

北极星指标建议为：**每位周活跃用户每周采用的任务成果数**。采用以用户明确采纳为准；复制、导出和打开文件作为辅助信号，不直接当作成功。

先邀请 5 位符合目标画像的用户，用自己的仓库完成三项任务：理解项目、找回之前的结论、审阅一项文本改动。记录首次成功耗时、需要提示的节点、补充背景次数和最终是否愿意使用结果。

首轮可用性门槛建议设为：5 人中至少 4 人能无帮助完成“理解项目”并定位依据。这个小样本只能用于发现明显阻碍，不能证明市场需求或留存。再观察两周内是否主动重复使用，以及不用时选择了什么替代方式。

同时记录任务开始、结果就绪、结果采用、失败类型、模板复用等本地事件以形成基线；产品分析无需采集原始对话与文件内容。性能目标、提升百分比与商业化判断应在有基线后再确定。

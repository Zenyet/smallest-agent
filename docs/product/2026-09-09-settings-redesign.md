# 设置 UI / UX 改版设计

日期：2026-09-09。范围：Electron 桌面端。基于当前设置组件、配置读写逻辑，以及使用模拟数据运行的实际渲染界面进行评估。本文与交互原型是设计提案，本轮未修改应用的设置实现，也未读取真实用户凭据。

实现状态：用户确认后已完成桌面端改版，见[设置改版交付说明](/Users/royzeng/lab/smallest-agent/docs/product/2026-09-09-settings-implementation.md)。下文保留设计时的分析与分期，不代表每项后续能力均已上线。

## 1. 设计结论

保留内嵌设置页、单侧导航及现有视觉体系。改版优先解决三个问题：

1. **找得到：**用户按要完成的事情寻找设置，不必先区分“凭据、能力、Agent 模式、检索”的技术边界。
2. **存得明白：**每次修改明确显示未保存、保存中、已保存或失败；保存与生效分别表达。
3. **知道能否使用：**已填写凭据、已启用引擎和连接验证成功是不同状态。

现有界面已经具备合理的基础：单列导航替换会话侧栏、内容限宽、分组表单、可编辑记忆、多厂商凭据。下一步集中改进这些流程，不增加独立设置窗口。

## 2. 当前问题与影响

| 优先级 | 观察到的实现 | 体验影响 | 改版处理 |
| --- | --- | --- | --- |
| P0 | 文本输入延迟 500 ms 保存，提交整份 draft；卸载时清除定时器 | 修改后立即返回可能来不及保存；不同字段的旧快照还可能覆盖新值 | 普通偏好按字段更新，串行或带版本提交；页面退出前完成待保存项，失败保留草稿 |
| P0 | 空字符串在校验时被跳过，存储采用对象合并 | 清空输入不代表已移除持久化值 | 增加明确的 unset 语义；区分“移除本机覆盖值”与“停用服务”，说明环境变量回退 |
| P0 | needsRestart 比较 draft 和 settings，保存成功后 settings 更新 | “已保存但未生效”的提示可能随保存成功消失 | 独立保存已应用版本与待应用变更，后端返回 pending 状态 |

| P1 | 常规标签、环境变量键名和较长解释同时出现；输入框固定 300 px | 技术信息抢占首屏，窄窗口标签区域受挤压 | 人话标题、简短影响说明；技术字段按需展开，输入布局随内容区宽度变化 |

## 3. 新的信息结构

| 新入口 | 包含内容 | 现有内容迁移 |
| --- | --- | --- |
| 模型连接 | 已添加服务、凭据、兼容端点、连接验证、导入 | 凭据页；采样参数移至高级 |
| Agent 与工具 | 内置 / 外部执行引擎、启用状态、环境检查、网络搜索、子任务 | Agent 模式 + 能力 |
| 记忆与资料 | 长期记忆、笔记资料两个页签 | 记忆 + 检索 |
| 对话偏好 | 逐字输出、请求缓存 | 通用 |
| 高级与诊断 | 执行轮数、重试、上下文压缩、采样、能力状态 | 高级 + 运行状态 |

首次进入：缺少内置模型配置时展示模型连接；已有配置时恢复上次分区。返回对话保留原会话和滚动位置。仍只有一份当前会话模型选择来源；设置中的服务编辑不能隐式切换模型。

## 4. 关键页面

### 4.1 模型连接

首屏以服务列表呈现，每次展开一项编辑；列表仍显示其他服务的配置状态。新增服务通过选择服务类型完成，避免常驻九个空凭据表单。

展开区域：

- 标题使用服务名，字段统一叫“API Key”，默认遮蔽，并提供显示 / 隐藏。
- 兼容端点增加地址和模型 ID / 模型清单；本地服务允许无 API Key。
- 编辑后显示“未保存”，启用“保存凭据 / 保存连接”及“放弃修改”。
- 保存后显示“已保存 · 未验证”；验证按钮检查当前已保存版本。
- 修改任一地址、凭据或测试模型后，之前的可用结果不再适用于新草稿。
- 网络失败显示原因和重试入口，同时保留已经保存的配置。
- 导入先说明“来源 → 目标服务”，用户确认后写入；不顺带切换当前模型。

**验证语义：**身份认证成功和模型请求成功需要分别处理。模型列表接口成功不能直接等同于某个模型可以生成回答，更不能证明图片、PDF 或工具调用均可用。真实验证返回本次测试模型、时间、配置版本和错误类别。若发送最小模型请求，应在按钮附近说明可能产生少量用量。

**配置来源：**若有效值来自环境变量或文件，应标记来源。“移除本机保存的凭据”可能恢复使用环境变量，不能展示成“已停用”。需要停用连接时提供独立状态，不能拿清空字段代替。

### 4.2 Agent 与工具

执行引擎使用名称、启用状态、环境可用状态三部分描述。已启用不代表已安装、已登录或已经完成 ACP 握手。

首版保留现有配置文件入口，但展示可操作的错误：未安装、未登录、适配器准备中、启动失败。重新检测由用户触发，不在打开设置时下载或启动所有适配器。

内置工具单独分组。子任务开关说明它会增加模型用量；网络搜索按选中的服务显示凭据，避免要求用户同时配置多个服务。外部 CLI 的权限由其自身管理，不能用内置工具的开关暗示统一控制。

### 4.3 记忆与资料

“长期记忆”展示自然语言内容，把 key 和 scope 的原始值放入开发者详情。支持全部 / 当前项目 / 全局筛选，项目名明确可见。

- 编辑和忘记按钮常驻，键盘聚焦清晰，不依赖悬停。
- 编辑使用明确保存 / 取消；Enter 保存、Escape 取消。失去焦点不直接提交。
- 单条忘记后提供可撤销反馈；真实实现需要可恢复删除记录或带版本的恢复操作。
- 关闭自动整理只关闭事后提取，不能表示模型再也不会记忆；提示仍可在对话中要求记住内容。
- 加载失败展示“读取失败 / 重试”，与“还没有记忆”分开。

“笔记资料”先展示当前目录、已应用目录及索引状态，再提供操作。目录用原生选择器；大多数用户无需看到嵌入模型和下载镜像参数。

**目标体验：**保存新目录后显示“已保存，等待刷新”；刷新成功后才切换到新索引。刷新失败保留旧索引并明确旧资料仍在使用。

当前运行时已有按需初始化和能力状态，但没有完整的目录热切换 / 手动刷新接口。原型中的刷新是后续目标流程。第一批如果仍需重启，应保留明确的“待重启”状态及已有运行中任务守卫，不能仅换成“刷新”文案。

### 4.4 对话偏好

保留轻量的两行布局，不为两个开关增加概览卡片。“流式输出”改为“逐字显示回答”；“磁盘缓存”改为“复用相同请求的答案”。

操作后显示保存反馈以及“下一轮生效”。当前任务继续使用开始时的配置；保存失败恢复控件的实际值，并在对应行说明原因。

### 4.5 高级与诊断

执行限制、上下文与采样、能力状态分组。低频参数放在展开区域；数字字段包含单位、默认值、合法范围和恢复该组默认值操作。

将“上下文上限”更名为“历史压缩阈值”：当前实现使用估算 token 数触发历史压缩，不是模型的硬上下文容量。范围需与具体后端约束一致；原型数值边界仅作交互示例。

诊断展示真实能力事件。尚未初始化、正在准备、可用、失败分别表达，不生成不存在的用量或性能分数。

## 5. 一致的保存与生效规则

| 设置类型 | 提交时机 | 保存后的反馈 |
| --- | --- | --- |
| 普通开关 | 立即按字段提交 | 保存中 → 已保存 / 行内失败；下一轮生效 |
| 数字参数 | 合法值在失焦或 Enter 时提交 | 非法输入不落盘；保留原生效值 |
| 凭据、端点、成组连接配置 | 显式保存，整组原子提交 | 已保存 · 未验证；验证是另一个操作 |
| 笔记来源 / 嵌入配置 | 显式保存 | 已保存 · 待刷新 / 待重启 |
| 记忆修改 | 保存按钮 / Enter | 已更新；失败保留编辑内容 |
| 忘记记忆 | 单条操作 | 可撤销；恢复冲突时不覆盖更新内容 |

设置容器保留各分区草稿，切页不会丢失。退出整个设置页时，完成普通偏好的待保存队列；只有存在显式表单草稿时才提供“保存并返回 / 放弃修改 / 继续编辑”。普通导航不反复弹确认。

后端建议返回 savedRevision、appliedRevision 和 pendingChanges。前端分别管理 draft、saved、applied，按字段或分组版本处理响应，防止旧保存结果覆盖新编辑。unset 应成为明确操作，不能依赖空字符串猜测意图。

## 6. 视觉与交互规范

- 延续现有 page / canvas / surface / field、三档文字和蓝色强调体系，默认沿用应用深色主题；原型同时随展示环境支持浅色。
- 保留同一窗口和单侧导航。生产界面沿用原侧栏宽度；内容区约 640–720 px，避免宽窗口中标签与输入分离太远。
- 页面标题约 22–24 px、组标题 14 px、正文 13 px、说明 12 px；主次关系靠字号和空间，而非给每层增加卡片。
- 凭据采用纵向标签与输入框，提高长地址的可读性；开关保留横向行布局；原始环境变量键名默认隐藏。
- 每组一个主操作；展开 / 收起使用 disclosure，不再使用开关表达“显示高级参数”。
- 窄窗口缩减侧栏和间距，表单保持可读；很窄的演示区域将导航换行，控件不横向溢出。
- 状态同时带文字，不只依赖颜色；编辑删除无需 hover；保存结果用 live region，错误关联到实际字段。
- 加载、空、失败、成功、未保存及待生效状态属于组件规格，不能只设计成功截图。

## 7. 交付切分

**第一批：设置页基础改版。**新的导航分组、字段文案与控件、开发者信息折叠、可见的保存反馈，以及按字段保存 / unset / 待生效状态修复。复用现有服务和记忆 API；先保证设置行为可靠。

**第二批：配置可验证。**补充连接验证、结构化错误、导入预览和引擎环境检查。验证不放在自动保存过程中执行。

**第三批：资料与记忆管理。**补充索引刷新、目录热切换、加载错误重试及可靠的忘记 / 撤销流程。按范围筛选可先使用现有事实数据完成。

组件建议拆分为 SettingsShell、ConnectionSettings、AgentSettings、MemorySettings、PreferencesSettings、AdvancedSettings，配合共享 SettingRow、SaveFeedback、ConnectionStatus 与草稿管理逻辑。避免继续向单个 SettingsPanel 叠加流程。

## 8. 验收重点

1. 新用户能找到配置入口；只配置一个服务即可验证并回到对话。
2. 快速修改两个字段、切页或立即返回，已确认的更改不丢失，旧响应不覆盖新值。
3. 清空与移除操作的界面结果、持久化结果和环境变量回退一致。
4. 保存需要重启 / 刷新的字段后，提示持续存在，直到实际应用成功。
5. 错误凭据不能显示可用；地址或模型变化后不沿用旧验证状态。
6. 导入凭据不切换当前会话模型；失败信息不暴露完整密钥。
7. 记忆读取失败不显示为空；删除可以按约定撤销，恢复不覆盖后续修改。
8. 键盘可完成导航、编辑、保存和返回；窄窗口下控件、标签与反馈不重叠。

原型中的连接、环境检测、保存、删除和刷新均在内存中模拟，不访问服务、不写入实际设置，也不构成这些后端功能已完成的声明。

原型检查：已查看深浅主题，以及 1,024 / 736 / 360 px 宽度下的布局；验证了连接状态变化、自定义端点无密钥保存、记忆编辑 / 删除 / 撤销、目录保存后待生效及刷新流程。JavaScript 语法检查通过，检查期间浏览器未报告脚本错误。

# 第一阶段交付：可信的首次体验

日期：2026-09-09。依据[产品优化方案](2026-09-09-product-opportunities.md)交付，范围为 Electron 桌面端及其共享 Agent 核心。

## 如何使用

1. 在仓库目录运行 `npm run dev:electron`，打开桌面应用。
2. 在设置中配置当前模型的 API Key。界面启动不再要求先配置密钥。
3. 打开新对话，点击「选择项目并开始」；已选中项目时点击「理解项目」。
4. 任务读取项目文件并生成说明。完成后检查「查看读取依据」和「查看完整成果」，再点击「采用成果」或「导出 Markdown」。

仍可直接在输入框自由提问。任务使用内置 Agent 和当前内置模型配置。

## 已交付

### 附件从输入到模型、历史记录的完整链路

- 图片、PDF、TXT、Markdown、CSV、JSON 可随问题发送，也支持仅发送附件。
- 文件读取期间禁止提前发送；失败后恢复输入与附件草稿，切换会话时不会串入另一个会话。
- 主进程校验附件格式、大小和 MIME；最多 10 个，单个不超过 20 MB，总计不超过 40 MB。
- 内置模型请求使用 SDK 的图片/文件格式，文本附件解码为文本；历史重载保留附件。
- ACP 根据 Agent 声明的图片与嵌入资源能力发送，不支持时返回明确错误；重连恢复历史时保留附件内容。

图片和 PDF 的理解能力取决于实际模型与 Provider。前端可以选取附件不代表所有模型均能理解该类型。

### 基础启动与可选能力分开

- 基础界面及消息处理先就绪；笔记 embedding 模型和索引在首次检索时初始化。
- 并发检索共享初始化过程，失败后下次检索可重试。
- 自建 MCP 在后台连接；笔记或 MCP 初始化失败只影响对应能力，界面可查看状态。
- 关闭期间完成的后台连接会被清理，不再发送过期状态。

### 「理解项目」与成果卡片

- 创建独立项目会话，整理用途、模块结构、运行方法、核心流程和待确认事项。
- 执行层仅提供文件系统的列目录、搜索、元信息与文本读取工具；不提供写入、命令执行或网络工具。
- 进度来自已完成的工具调用；成果卡保留实际读取成功的文件片段，便于人工核对。
- 只有取得文件依据且输出非空时才进入「待验收」，由用户明确点击后标记「已采用」。采用只改变成果状态，不修改项目文件。
- 支持导出 Markdown；取消保存不会显示导出成功。
- 状态、说明及依据本地持久化。重启后恢复成果；此前正在运行的任务标记为「已停止」，不会冒充完成或自动续跑。

依据最多保留最近 32 个不同文件，每份最多 3,000 字符，并标记截断。它们是执行时的读取片段，不是对全部结论正确性的自动认证。
